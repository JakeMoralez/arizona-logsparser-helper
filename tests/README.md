# Проверка модальных окон

Нужны Node.js и доступный пакет Playwright с Chromium. Новые зависимости расширению не требуются.

Запуск: `node tests/modal-ui.test.cjs`. Если Playwright установлен отдельно, задайте `PLAYWRIGHT_MODULE` (путь к пакету) и при необходимости `PLAYWRIGHT_BROWSERS_PATH`.

Тест поднимает временный сервер только на `127.0.0.1`, использует реальные менеджеры меню из исходников и подменяет сетевые запросы, уведомления и буфер обмена. Реальные логи и учётные данные не используются. Скриншоты сохраняются в `test-results/`.

`node tests/startup.test.cjs` проверяет полный порядок content scripts с синтетической страницей и подменой всех сетевых обращений: задержанные настройки и геоданные, 500 строк, две темы, Sakai, отключение, вход, защитную страницу, ошибку и таймаут. После готовности сравнивает геометрию страницы и измеряет CLS.

Проверяются даты, время, диапазоны, синхронизация значений, клавиатура, динамические поля, вложенные окна, параметры запуска проверок, генерация и копирование команд, сохранение/поиск/удаление шаблонов и размеры всех четырёх меню в двух темах.

`node tests/page-controls.test.cjs` проверяет основные селекты, множественный выбор 0/1/5/50 типов без изменения высоты поля и удаление выбранных значений, дату со временем до секунд, параметры FormData, быстрые фильтры, сброс, подгрузку логов, перенос формы в окно фильтров, закрытие фоном, массовые действия и закрепление шапки. Скриншоты — для ширин 390, 1101, 1201, 1254 и 1440 px в обеих темах.

Для проверки в установленном расширении: обновите его на странице управления расширениями, перезагрузите LogsParser и проверьте запросы к реальному серверу. Эти запросы автоматический UI-тест не выполняет.

Фикстура основной страницы использует плоскую форму с 350 скрытыми динамическими полями и внешними Bootstrap-строками. Проверяются три собственные секции формы, ширина многострочного ввода, цвет поискового поля при конфликтующих стилях сайта, длинные значения таблицы, отсутствие переполнения документа и открытые списки в окне фильтров.

`node tests/table-ui.test.cjs` проверяет классы полей с суффиксами без базового класса, обёртки карточки и конфликтующие размеры прямых детей формы. Также проверяет Shift+клик/Shift+Space, диапазоны в обе стороны, скрытые строки, подгрузку и замену tbody, единственное обновление счётчика, кнопку глаза 24×24, границы IP-столбца и окна предмета/результата онлайна.

`node tests/performance.test.cjs after` выполняет по три прогона на 100, 500 и 1000 строках. Отдельно измеряются загрузка, установившийся простой, массовое выделение, прокрутка и открытие фильтров: JavaScript, layout, пересчёт стилей, длительные задачи и DOM-запросы. Paint сохраняется в общей трассе. Медианы и исходные результаты — в `test-results/performance-after.json`, трасса для 1000 строк — в `test-results/trace-after-1000.json`. Для сравнения с другой копией исходников задайте `ALH_CODE_ROOT` и метку последним аргументом; `ALH_PERF_ROWS` и `ALH_PERF_RUNS` позволяют выполнить целевой прогон. Измерения выполняются только в тестовом браузере.

`node tests/geo-layout.test.cjs` проверяет две IP-метки, отложенную геолокацию, длинное расстояние и описание: границы всех добавленных элементов должны находиться внутри ячейки. Скриншоты снимаются на пяти ширинах в обеих темах.

`node tests/runtime.test.cjs` проверяет передачу управления между кадровыми задачами, отмену, единственный общий IntersectionObserver, пакетную доставку, позднюю подписку и очистку подписок при замене строк.

`node tests/ui-refinements.test.cjs` проверяет роли основных кнопок, дополнительные быстрые периоды, ввод `1100 → 11:00`, SVG-шеврон, передачу нескольких типов в URL выгрузки, сохранение scrollY после окна предмета, оформление стандартного окна информации и плавающую панель. Скриншоты включают непрозрачный поиск над прокручиваемыми вариантами в Storm Cloud и светлой теме.
